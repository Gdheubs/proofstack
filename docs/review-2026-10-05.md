# ProofStack checkpoint — 5 October 2026

This continues the Phase 3 review from 4 October. The previous review is retained as history; this document describes the latest changes and verification.

## Implemented

- Batched feed authors, mentions, comments and reactions. The 21-post SQL fixture, including distinct authors, comments, bookmarks and reactions, asserts a ceiling of seven database queries. This is a query-count regression test, not a load-test result.
- Added batch profile preloading for project contributors, organization members, team members, search and follower lists. Organization counts are retrieved with the organization query. Some project/team detail queries still run per resource and remain candidates for further batching.
- Blocked project and organization deletion when clearing a project link would reveal hidden posts. Authors must explicitly delete or detach those posts first. The SQL regression exercises both actual deletion actions and last-owner protection.
- Added `pnpm test:embedded`: isolated PGlite SQL engines apply tracked migrations and run the schema, authorization, visibility and feed regression suites without a separately installed database. Only this test configuration uses the direct test transport adapter.
- Added optional `API_INTERNAL_ORIGIN` routing for local/standalone Next.js use. Existing Replit routing remains the default when the setting is absent. Set the exact server-side HTTP(S) origin before building production output.

## Verification limits and next gates

The native PostgreSQL CI suite is still required. PGlite executes PostgreSQL SQL, but its test adapter does not prove native driver transport, TLS, pool behavior or concurrent transactions. An attempted socket-based run exposed adapter protocol trouble during error recovery; the regression assertions were retained and passed through the direct SQL test adapter instead.

Browser automation could not run because browser installation failed in this runtime. HTTP checks do not establish client hydration, responsive layout, keyboard behavior or interactive/authenticated journeys. No live identity credentials, SMTP/SMS delivery, storage permissions, OAuth callbacks, load tests, backup restore or deployment were verified.

Phase 3 still needs those staging acceptance gates. Phases 4–7 remain future implementation work; linked repository/evidence records are not actual Git hosting, pull requests or an executable CI platform. See `roadmap.md` for the sequence and `setup.md` for the deployment environment.
