# ProofStack checkpoint — 6 October 2026

Resumed the in-progress Phase 4 checkpoint and completed the first native Git milestone. Phase 3 careers and collaboration features remain included. This is a tested source checkpoint, not a deployed or production-certified service.

## Implemented

- One native bare Git repository per project, with visibility and access inherited from the project and its organization.
- Branch creation, protected main, bounded UTF-8 file creation/edit/deletion and real commits with account-specific noreply author identities.
- Source tree browsing, file views, branch selection, paged commit history and reachable historical snapshots. Framework paths such as `app/(site)/[id]/page.tsx` use literal Git path handling.
- Public clone/fetch and private clone/fetch through Git smart HTTP, using expiring repo-scoped read tokens. Tokens are stored hashed, issued only after native MFA, revocable and checked against current active identity/access. External push, SSH and code execution are disabled.
- Database-authoritative branch heads, row-serialized operations, optimistic expected-head checks and audit events. Physical refs are rebuilt from database state before reads; regression tests simulate a lagging filesystem ref and confirm recovery.
- Dedicated storage configuration, quotas, bounded output/time/concurrency, safe paths, minimal Git environment, disabled hooks/protocols, no checkout, and process-group termination on timeout/output overflow.
- Migration `0006_handy_starbolt.sql`, generated API contracts, modular UI components and setup/backup/recovery documentation. Repository storage remains disabled unless REPOSITORY_ROOT is explicitly set.

## Verified

- 72 unit/regression tests pass, including native Git objects, nested source, file deletion, path validation, quota failure and missing-storage behavior.
- Six embedded SQL workflow tests pass. The new workflow exercises project permissions, protected main, contributor branches, stale-edit rejection, historical views, physical-ref recovery, MFA, token hashing/revocation and private-project access.
- Real `git clone` succeeds through the running Express HTTP service for public and authenticated private repositories; real `git fetch` retrieves a newly created branch and its source. Anonymous private clone, revoked-token clone and push advertisement are rejected.
- ESLint, formatting and TypeScript checks pass. The Express API and Next.js production builds pass.
- Production HTTP checks pass for 17 page routes, API proxying, anonymous private-view rejection, database readiness and the disabled repository-storage configuration gate.

The Git client/CLI is real. The database workflow uses the test-only PGlite adapter; it does not establish native PostgreSQL transport, TLS, locking under concurrent processes or storage power-loss durability. HTTP tests do not establish browser hydration, responsive/keyboard behavior or live managed-identity MFA journeys.
